Lesson 0001 · Foundations

The Safety Net

Why a "worktree" is just a safety net you can walk back through

You said the thing you fear most is lost or corrupted work. Good — that fear is the right one, and it's the reason the rest of this course exists. Before we touch any of Claude Code's four parallel tools, you need one thing underneath them all.

A commit is a photograph

Most people's mental model of git is "save button with extra steps." That's why it feels dangerous. The real model is simpler and safer than that:

A commit is a photograph of your entire project at one moment, with a label.

Not a diff. Not a list of changes. The whole thing, frozen, with a name you chose. Git keeps every photograph you've ever taken, forever, in a row.

c1→ c2→ c3→ c4 you are here

If an agent destroys your code, the answer isn't "carefully next time." The answer is: you're standing at c4, and c3 is still right there.

The one sentence

Git does not let you lose work. It lets you lose time. Those feel different at 2am.

Working tree vs commit

Two words that cause most of the confusion. And you will need them for lesson 0002, because "worktree" is a compound word that uses both.

TermWhat it isAnalogy
working tree The live folder on your disk. Where unsaved edits sit. Fragile. Your desk
commit One frozen snapshot in git's permanent history. A photograph in a drawer

An agent editing a file changes the working tree. That is the dangerous state — nothing is recorded yet. A commit is what makes it safe.

This is the bug we hit earlier

Recall the experiment: three agents produced perfect isolated work, and none of them committed. Their branches were empty labels pointing at the same commit. All that work existed only as loose files on disk — one bad command away from gone.

This is the single most important practical habit in this whole course: isolation without a commit is not a backup.

Now: what a branch is

A branch is not a copy of your files. This is the myth that makes git feel dangerous.

A branch is a movable label pointing at one commit. Creating a branch costs nothing and copies nothing. It's an arrow.

The reframe

You don't "make a copy to be safe." You make a label to mark where you are. That's why branches are instant and cost nothing — there's nothing to copy.

So what IS a worktree?

Now the word makes sense. It is a working tree on a different branch.

worktree = a second working tree + a branch label pointing elsewhere

Two separate things, glued together:

  • the working tree — a real folder on disk where edits are fragile
  • the branch — a label marking which commit you're building on

That's why a worktree makes work safe on two axes at once. If the folder gets wrecked, the branch label still points at your last good commit. If the branch gets confused, the folder still has your files. Either one alone would be a weaker guarantee.

Run this yourself

You've already done this. In this very repo:

git log --oneline 7b795ec chore: scaffold toy project with failing stubs a95a6b9 feat(a): implement shout 86377f8 feat(b): implement double 91f1e1d feat(c): implement sum 308941f feat(d): add triple with tests and README

Every line is a photograph. The agents' work from two experiments ago is sitting right there, still perfect, still labelled.

Your turn

Run git log --oneline in this repo. Then answer these three out loud, or just type them:

1. What is the newest photograph?
2. What does it say at the end of its message?
3. If you deleted every file right now, what single command brings it all back?

Question 3 is the whole point of this lesson. If you can answer it without hesitating, you're ready for lesson 0002.
