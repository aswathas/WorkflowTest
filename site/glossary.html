Phase 00 — Setup & Tooling

TermWhat people sayWhat it actually meansLesson
working directory"the project folder"One specific folder a command runs in. Not a default. Not negotiable per command.1
repo root"wherever I ran git init"The top folder of the repo, found with `git rev-parse --show-toplevel`. Subfolders are inside it but are not it.1
git config"git settings"Identity and defaults, stored per-machine globally and per-repo locally. Without identity, commits fail.1
prompt"the thing with the cursor"The text your shell prints before each command. Make it carry path and branch, and you stop needing to check.1
Working tree"The folder where my code is."The files on disk right now, as your editor sees them. Uncommitted changes live here and only here.2
Staging area"A place to review changes before committing."A snapshot of selected working-tree files, prepared for the next commit. The staging area is not a backup — it is a holding pen.2
Local repository"Where commits are stored."A database on your machine that records every commit. This is the safety net. Once a change is committed, it is recoverable until you delete the `.git` directory.2
Remote"Where I push code so others can see it."A copy of your repository on another machine. For solo AI-agent work, the remote is insurance against losing your laptop, not a way to collaborate.2
Commit"A saved change."A snapshot of specific files at a specific moment, with a message describing why. Commits are the unit of recovery.2
`git restore`"Undo."Reverts a working-tree file to its state at the last commit. Use it when an agent — or you — has wrecked something and you want the last known-good version.2
shell"the terminal"The program that interprets what you type. The terminal is the window; the shell is what runs inside it.3
command"a line of code"One verb the shell runs, with arguments after it. `grep -rn "x" src/` is one command, not five.3
redirect `>`"save output"Overwrite the file on the right with the left side's output. If the file existed, it is gone.3
redirect `>>`"append output"Add to the end of the file. The old contents survive.3
flag"option", "switch"A single-letter or single-word argument after the verb that changes its behaviour. `-r` in `rm -rf` means recursive; `-f` means no confirmation.3
working directory"the project folder"One specific folder a command runs in. The agent inherits yours; if it `cd`s, it does so only inside its own tool call.3
**Format-on-save**The editor pipes the file through a formatter every time you saveSome people treat formatting as a manual chore, or as "what the agent should remember." It is neither. The editor does it, invisibly, every save — and with an agent in the loop, "what the agent should remember" is the worst possible plan.4
**Integrated terminal**A shell pane inside the editor window, sharing its working directoryPeople think of terminals as separate apps. With agents, you spend half your time in shell and half reading code. A switch costs attention, not seconds, and attention is what you are trying to spend on the change.4
**Project-wide search**A single-keystroke regex search across every file in the project, with a jumpable hit listPeople confuse it with "find in current file." Current-file search finds text. Project-wide search finds code — including hits in files you did not know mattered. With agents, you almost always want the latter.4
**Test runner**A program that runs the project's tests and reports pass/fail per file or per case, bound to one keyPeople treat tests as something you "remember to run." A test runner bound to one key is the difference between remembering and not — and between verifying and trusting the agent's word.4
**Save**A signal to the editor that the buffer is ready, plus a trigger for hooks like formatters and lintersSave is no longer just "write the file to disk." In an agent workflow, save is the moment the diff stops being dirty, the formatter runs, and you cross from "agent is still typing" to "agent is done, and you can review."4

hallucination"it made something up"Correct. It produced the most plausible continuation given its input. Plausibility was the training objective; truth was never a term in the loss.6
weights"the learned knowledge"Enormous learned numbers encoding statistical regularities of text. Not a database, not searchable, not inspectable as facts.6
training data"what it knows"Text it was fitted on. It cannot cite it, cannot check whether it is still current, and has no access to your repo.6

confident"it's sure"The writing, not the model. Tone is generated, never calibrated.6
ground truth"the right answer"Whatever you can verify independently — a file, a test, a doc. The model is not a source of it.6
token"a word"A sub-word unit from a trained tokenizer. Roughly four English characters, but a split point inside a word, so length in characters does not predict it reliably.7
tokenizer"the splitter"The trained program producing those units. Each model family has its own, which is why token counts are not portable across models.7
input tokens"the prompt"Everything sent, including conversation history, file contents, tool definitions, and system instructions — not just what you typed.7
output tokens"the reply"What the model generated, including thinking where extended thinking is on.7
context"the chat"The full body of text the model sees on the next turn. Grows with every message, read, and tool result.7
re-send"it remembers"The entire conversation is transmitted again on every request. Long sessions tax each new message.7
context window"the chat history"Every token the model sees next turn: instructions, tool definitions, files, command output, and the conversation. One budget for all of it.8
context"what it remembers"The whole re-sent body. It is re-transmitted, not recalled from a store.8
compaction"it forgot"Automatic or manual summarization of older history to make room. Loses detail by design.8
survives compaction"it's still in context"Depends on how it got there. Files and root instructions are re-read; the middle of the conversation is not.8
`/clear`"new chat"Empty window, new conversation. `/resume` reopens a cleared one.8
window size"how much it can hold"A per-model, sometimes per-configuration number. Move it and you break this lesson — check `/context` and the docs.8
prompt"what I typed"The whole assembled input: your text, system instructions, tool definitions, project files, and all history.9
inference"the model thinking"One forward run producing output from input. The only thing you pay for.9
training"when it learns"Fitting the weights, offline, before you ever prompted. Not something you trigger.9
API"the model"A network interface with a request, a response, and token counts. Something can break at either end.9
temperature"how creative it is"How much the sampling distribution is flattened. Low is repeatable, high is varied.9
max output tokens"the length cap"The ceiling on one response. Hitting it truncates mid-answer.9
system prompt"its instructions"Harness-supplied behaviour rules, injected every request. Not yours, and often larger than yours.9
agentic"it's autonomous" / "it's smart"A loop: model decides, tool executes, result returns, model decides again. No magic adjective.10
agentic loop"the magic"That repeat. Gather context, take action, verify, repeat until done.10
harness"the CLI"The layer around the model: tools, context management, permissions, the loop itself.10
tool"the agent's hands"A named action the model can request. Every tool result becomes the next input.10
tool result"the output"New information fed back in. An empty or wrong result corrupts every step after it.10
verification"it checked"Running something capable of detecting the problem. Most self-checks cannot.10
surface"it should have known"The set of tools available. Missing a tool looks exactly like missing capability.10
checkpoint / rewind"undo"Harness-level restore of file contents, separate from git. Does not cover actions against remote systems.10
latency"the model is slow"Wall time per turn: many network round trips plus generation. Usually round trips, not thinking.11
round trip"a step"One request to the model and back. Each one re-sends context. Cost and latency both scale with the count.11
rate limit"quota"The provider's ceiling. Requests are refused or queued; nothing you write changes it.11
prompt cache"it remembered"Previously-processed content served at a reduced rate. Expires on a TTL, then costs full price again.11
cache read"free"Reduced-rate reuse. High proportions mean efficient work; misses mean something invalidated.11
tokens per million"the price"Unit pricing for input and output. Changes — read it live, never from memory.11
`/usage`"the bill"Session cost, plan limits, and a usage breakdown. Estimated from token counts, not an invoice.11

Phase 02 — Git Deep

TermWhat people sayWhat it actually meansLesson
commit"saving my changes"A frozen full tree with a message and a parent. Content-addressed.12
diff"the commit"The *difference* between two trees. Useful to read; never what is stored.12
staging area / index"the thing before the commit"A draft tree. `git add` edits the draft; `git commit` freezes it.12
`git add -p`"partial staging"Choose change-by-change inside one file instead of all or nothing.12
commit hash"the commit id"A digest of the commit's contents. Change any byte, including the message, and it changes.12
`--amend`"fixing the last commit"Replaces the last commit. Fine locally, disruptive once pushed.12
`git revert`"undo"New commit that undoes an old one. History stays honest.12
branch"a copy of the project"A file containing one commit hash. Creating it copies nothing.13
HEAD"my current branch"A label that usually points at a branch. Points at a commit directly = detached HEAD.13
detached HEAD"broken git"HEAD points straight at a commit. Valid, but commits made here are only reachable via reflog.13
`git branch -d`"delete a branch"Deletes the label. Refuses if the branch holds unmerged commits.13
`git branch -D`"force delete"Deletes the label anyway. Commits survive until garbage collection, then may not.13
reflog"undo for branches"Local record of every HEAD and branch move. Your first stop when a branch "disappeared".13
`git switch`"checkout but better"Moves between branches only. `restore` handles files.13
merge"joining branches"Combine two lines and record the join. Adds a merge commit with two parents when needed.14
rebase"cleaning up history"Replay your commits on another base. New hashes, same changes. Safe only on history nobody else has.14
fast-forward"a merge"A merge where one line has no new commits, so the label just slides. No merge commit.14
merge commit"the merge"A commit with two parents. The explicit record that two lines joined.14
`git pull`"getting the latest"`fetch` plus a merge or rebase you did not choose. Use `--rebase` / `--no-rebase`.14
rebasing shared history"fixing the branch"Produces two incompatible versions of the same commits. Every later merge sees the change twice.14
`git rebase --abort`"undo"Bails out of an in-progress rebase. Nothing was committed yet.14
conflict"git broke my file"Both sides changed a region and git declined to guess. The markers are the question.15
`ours`"my change"The branch **you are on right now**. Not "the change I like".15
`theirs`"their change"The branch you merged in. Reversed during a rebase.15
resolved"the markers are gone"The file has been `git add`ed. Until then the merge cannot complete.15
unmerged path"broken file"A path git still considers unresolved. `git status` names them.15
merge driver"smart merge"Configured handling for files that should never need human resolution.15
`git merge --abort`"start over"Returns to the pre-merge state. Only while the merge is in progress.15
recovery"undoing my mistake"Moving a label back. The commits were never deleted.16
`reset --soft` / `--mixed`"soft reset"Moves the branch; keeps your working tree. Safe.16
`reset --hard`"starting over"Moves the branch and overwrites tracked files. **The only command here that can destroy uncommitted work.**16
`git revert`"undo"A new commit that undoes an old one. Correct on shared history.16
reflog"undo for git"Every position each label has held, in order. `HEAD@{n}` indexes it.16
`ORIG_HEAD`"the backup"Where HEAD was before the last merge or reset.16
garbage collection"cleanup"When unreachable objects are actually reclaimed. Gives "recoverable" a shelf life.16
untracked file"my file"Not in git's object store. `reset --hard` will not delete it; `git clean` will.16
stash"hiding my work"A commit on a hidden branch holding uncommitted changes. Restorable, and subject to gc.17
`git stash -u`"stash"The variant that also takes files never added to git. The plain one skips them.17
`pop` vs `apply`"the same"`pop` restores and deletes the entry; `apply` keeps it. Keep it when the restore conflicted.17
working tree"my files"The live folder. The only place uncommitted work exists, and the only thing `reset --hard` can destroy.17
destructive delete"the agent cleaned up"An agent removed a file it never read. Cheap to undo *if* committed.17
thrash"it iterated"Multiple rewrites of one file in a turn. Only the diff shows whether it improved.17
scope creep"it helped while it was there"Changes outside the ask. `git status` is the only reliable detector.17
remote"the copy on GitHub"A label for a URL. Git does not sync to it automatically.18
`origin`"the remote"The conventional name for the one you cloned from. Renameable.18
`upstream`"the original"The conventional name for the original when you cloned a fork.18
`origin/main`"main on the server"Your cached record of it, from your last fetch. Can be stale.18
`git fetch`"getting updates"Updates the record only. Never touches your tree or branches.18
`git pull`"getting updates"`fetch` + a merge or rebase you did not choose.18
fork"a copy I made"A server-side copy of someone's repo, so you have push access.18
pull request"a git merge"A review request on the hosting platform. The merge itself is a git operation.18
`--force-with-lease`"safe force push"Force-push that refuses if the remote moved since your last fetch.18

Phase 03 — Models & Families

TermWhat people sayWhat it actually meansLesson
Open-weight"Open source AI"The weights are a downloadable file. The training data and code may not be public. "Open weight" and "open source" are not synonyms.19
Frontier"The biggest model"The model with the best capabilities at a given time, typically large and run by a major lab. Size correlates, but the defining trait is capability leadership, not parameter count.19
Weights"The brain of the model"The millions or billions of numeric parameters learned during training. Public weights mean anyone can run the model.19
Fine-tune"Train the model again"Continue training a downloaded model on your own data so it behaves the way you want. Only possible with open-weight models.19
Quantized"Compressed model"The weights stored at lower precision (e.g. 4-bit instead of 16-bit) so the model fits in less memory. Slight quality loss for a big size drop.19
alias"a shortcut"A name for a family and a job that resolves to the current model on your provider. Survives version bumps.20
model ID"the model name"One exact version, frozen in time. Correct to reproduce a run; rots as a default.20
resolution"it just picks one"Alias → provider → concrete model. The provider decides, and it can differ between providers.20
`default`"the default model"A special value that clears an override and returns you to your account's runtime default. It is not a family.20
`opusplan`"Opus for everything"Opus in plan mode, Sonnet in execution. Two models, one session, two caches (Lesson 22).20
pin"hardcoding"Naming a specific version deliberately. Legitimate with a written reason; a bug without one.20
effort level"how smart it is"How much adaptive reasoning the model is willing to spend, decided per step. A cost dial, not an intelligence dial.21
adaptive reasoning"thinking"The model deciding, step by step, whether thinking is worth it. Effort sets the appetite; the step decides.21
extended thinking"the reasoning"The tokens the model emits before its answer, billed as output. Visible with `Ctrl+O`.21
thinking tokens"free scratchpad"Output tokens like any other. You pay for thinking even when it is collapsed or redacted.21
`ultrathink`"a magic word"A keyword that requests deeper reasoning for one turn without moving the session's level.21
`max`"the best setting"The deepest level, session-only unless set through the environment. Prone to overthinking; test it before adopting it.21
prompt cache"it remembered"Server-side reuse of a request prefix you recently sent. Not memory between turns.22
prefix"the start"The exact beginning of the request matched against the cache. A change anywhere in it recomputes everything after.22
cache read"free"Reduced-rate reuse of cached tokens. High read-to-write means caching is working.22
cache write (creation)"the miss"Tokens written into the cache on this turn, at the cache-write rate. High every turn means your prefix keeps changing.22
invalidation"cold cache"The prefix no longer matches, so the next turn reprocesses the whole request and writes a new cache entry.22
TTL"how long it lasts"The idle period the cache survives. Every hit resets it; a long gap means the next turn can miss.22
quantization"compressing the model"Storing the same weights at lower precision. Smaller and faster, knowledge unchanged, slight quality loss.23
precision / bit-width"how many bits"How many bits store each weight. Eight, four, and smaller are common; lower means smaller and a little lossier.23
distillation"shrinking the model"Training a small student to imitate a large teacher's outputs. A new, smaller model with the teacher's behaviour on covered inputs.23
teacher / student"the big one and the little one"The capable model producing training targets, and the small model learning from them.23
fine-tuning"training it more"Continuing training on your own data so the model picks up your domain. Needs the weights, and a check set.23
check set"the tests"Held-out examples with known good answers, scored before and after, so you can tell improvement from drift.23
confidently wrong"hallucinating"A fluent, wrong answer. The failure mode fine-tuning can amplify, because it learns your data's errors too.23
SLM"a weak model"A small language model, roughly hundreds of millions to a few billion parameters. Weak at open-ended reasoning; often enough for a narrow task.24
parameter count"how big it is"The number of learned weights. A description, not a definition of capability (Lesson 19).24
narrow task"simple task"A task with a small, fixed set of correct answers. Narrow is about the output space, not the difficulty of the input.24
throughput"how fast"Calls handled per unit time, locally and without a network round trip. Why small models win at volume.24
crossover"the break-even"The volume at which a per-call cost difference outweighs an accuracy difference. It is arithmetic, not taste.24
confidently wrong"hallucinating"Fluent and incorrect. The failure a small model hits hardest when the task is open-ended and unchecked.24
decision model"a classifier"A model built to return a label, score, or choice rather than open-ended text. Small, fast, cheap.25
generation model"the chatbot"A model that produces open-ended text. Right for writing, wasteful for a yes/no.25
decision call"a simple call"A call whose answer is one of a fixed set. Cost is dominated by the output you did not need.25
label set"the options"The fixed choices a decision can return. A small, closed set is what makes a small model viable.25
output tokens"the reply"What the model generated. The cost driver when a decision is answered with a paragraph.25
confidence gate"escalate when unsure"Sending only the uncertain decisions to a bigger model. Phase 14 builds this; here you only need the pattern.25
LLM"the model"A large language model. A size description; says nothing about output shape or where it runs.26
SLM"the weak one"A small language model. A size band, mostly on the open-weight side, most useful for narrow decisions.26
decision model"a classifier"A model that returns a label or choice. An *output-shape* category, independent of size.26
generation"talking to the model"Open-ended text output. The category that needs a larger, broader model to do well.26
open-weight"you can download it"The weights are public, so you run it yourself (Lesson 19). A *serving* category.26
frontier"the best model"The most capable model at a given time, hosted for you. A serving category, and it moves.26
output shape"the answer type"Label versus open-ended text. The axis that decides which model to use.26
routing"picking a model"Choosing a tier per call from task shape, and defending the choice.26

Phase 04 — Claude Code

TermWhat people sayWhat it actually meansLesson
**"Chatbot"**A program you talk to in turns, one prompt at a timeClaude Code looks like a chatbot in the terminal, but it is shaped for goals, not turns. Calling it a chatbot trains you to use it like a chat box.27
**"AI assistant"**The assistant is you; the tool is the thing doing the workWhen you call it an assistant, you picture yourself giving instructions. When you call it a tool, you picture yourself choosing when to use it. Different verb shapes the work.27
**"Agent"** (here)A program that takes a goal, picks its own steps, and uses tools to make progressIn casual use "agent" means any AI that acts. In this course it means specifically: it decides what to do next, you approve. That distinction is the whole point of Phase 04.27
**"Completion"**The model finishes the text you startedChat interfaces are completion-shaped. You write, it writes. Claude Code is goal-shaped. You describe the destination, it picks the route.27
**"Terminal tool"**A program you launch from a shell, that runs with your project's files and permissionsSome "AI tools" are websites that look technical. A terminal tool can actually touch the project you are in. That is the affordance none of the others have.27
